## Shape (impeccable shape, run on the surface after the V2 merge)

Impeccable `context --target src/browse/DestinationsTab.jsx` ran from the T384 root worktree and loaded PRODUCT.md and DESIGN.md. Shape's discovery round has no human to ask in this unattended run (owner instruction 2026-10-07), so the brief below states its assumptions and does not wait.

1. Job and audience. An undecided budget traveller, hiker first, narrowing the published walks, beaches, lakes, summits, cycle routes and trips to the two or three worth opening. Mode: Operate (scanability and consistency outrank expression).
2. Outcome. The right place opened in under a minute, from a first screen that is short enough to see the list, with every control that narrows the list reachable on both widths and every active filter visible and removable.
3. Direction. Refinement, not redesign: the palette, the three faces, the one card, the three bands of the opening and the coverage voice stay. What changes is order, reach and weight.
4. Scope. Structure, information and flow only (V3). No caption bands, no gradient removal, no cost line, no month fact, no sticky row: those are V4 items of the brief and wait for that wave.
5. States. Rest (opening bands), loading, filtered, searched (catalogue and anywhere), near mode, a country, empty by filter, empty by coverage, layer error, the Trails country index.
6. Assumptions, because no human answered: the cold-start category stays Trips (row T373-c is the owner's); the coverage line's copy waits on the owner (row T373-e); no alternate place names exist on the wire (checked: `public/dest/BE.json` holds "Ghent" with no local name), so search ranks names but cannot find "Gent".

## The changes, in order

0. T375-a first. `countryName` in `src/browse/DestinationsTab.jsx` throws a RangeError from `Intl.DisplayNames.of` when a link carries no country (`#tour=`). Guard it: an empty code returns an empty string, and a code the engine refuses returns the code itself.
1. T373-a. Build the app before any change and run the six harnesses on `vite preview`, in order, one browser at a time. Record the baseline per harness and which assertions encode removed screens.
2. V3-1, one short facet set inline, the long set in the sheet, on both widths. Inline (phone toolbar and desktop panel) shows only groups flagged `toolbar` (one per layer: water quality, swimming, how to reach the top, length for cycling, length for walks, pace and scale for composed trips), plus any group with a chip on. The desktop panel gains a secondary "All filters" button with the active count that opens PlacesFilterSheet with every group. Files: DestinationsTab.jsx, 63-v6-destinations.css, six catalogues.
3. V3-2, active filters as one removable chip row above the list, using shell's `src/browse/FilterChips.jsx` unchanged (N6): every chip that is on, the country and the near place, ending with "Clear all", which returns the section to its opening. Files: DestinationsTab.jsx.
4. V3-3, the six categories as a 2 x 3 grid of equal buttons on a phone (N9), the accent tick above each tile removed (shell R11), the active tile `--ink-fill` with `--on-fill`. One keyboard model: the categories become `aria-pressed` toggle buttons in a labelled group (they carry `role="tab"` today with no arrow keys and no tabpanel). The phone strip rules move out of `24-destination-workspace.css` into 63. Files: DestinationsTab.jsx, 23-places-pages.css (old rule out), 24-destination-workspace.css (moved rules deleted, OWNERSHIP rule 5), 63-v6-destinations.css.
5. V3-4, panel words. "Filter categories" and "Filter specifics" (shell keys `side.categories`, `side.refine`, which Explore and My trips also read) are replaced on this tab by keys of its own, "Browse" and "Narrow the list". Files: DestinationsTab.jsx, six catalogues.
6. V3-5 and V3-12, a shorter opening. Band 1 shows six icons (ICON_MAX 6). Band 2 shows the first two rails on a phone and the rest as one row of cut chips calling the same "See all" (N4); desktop keeps every rail. The first rail per section is the section's leading need: water tested excellent (beaches), warm enough to swim in June (lakes), reachable without a car (mountains), mostly away from traffic (cycling) and, new, "Half a day to a day (5 to 20 km)" for walks, which saves the existing half and day bands together. Files: `src/lib/openingScreen.js`, `src/browse/SectionOpening.jsx`, DestinationsTab.jsx, 63-v6-destinations.css, `tests/openingScreen.test.mjs`, six catalogues.

A new pure module `src/lib/placeSearch.js` (destinations, with its OWNERSHIP.md row in the same change) and a unit test `tests/placeSearch.test.mjs`.
8. V3-8, remembered browse state (N10). Category, country and near place in localStorage under one key, every read and write in try/catch, the tab correct without it; a link that names a category, country or place still wins.
9. V3-10, the Trails country index. Each country card carries its count of published walks in mono beside the name (N7, from the trails index the tab already loads), a card with no cover shows the flag on `--paper-dim` instead of the two-letter monogram, and "Walks near me" (the existing locate) sits above the index where the browser can locate.
