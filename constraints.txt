# 2026-09-27 (T048, register row T046-h). Use them on every host:
#
#   python -m pip install --only-binary=:all: -r requirements.txt -c constraints.txt
#
# Why: requirements.txt has floor pins only, so a fresh venv resolves the
# newest releases (pandas 3, numpy 2, scikit-learn 1.9 on 2026-09-27) while the
# laptop, whose output the pipeline has always shipped, runs pandas 2.2.3,
# numpy 1.26.4 and scikit-learn 1.6.1. This file makes the Linux orchestrator
# resolve what the laptop runs. It is a constraints file, not a lock: it pins
# versions but installs nothing requirements.txt does not ask for, and a
# package absent from here floats.
#
# How it was made: the full dependency closure of requirements.txt was resolved
# for the orchestrator's platform (uv pip compile --python-platform
# aarch64-manylinux_2_28 --python-version 3.12 --only-binary :all:), and every
# package in it pinned to the version installed on the laptop
# (importlib.metadata). The same compile run against these pins resolves all
# of them with a Linux aarch64 CPython 3.12 wheel or a pure-Python one.
# T299 ran the same compile with --python-platform x86_64-manylinux_2_28 for
# the x86 fallback box: all 71 resolve, at versions identical to aarch64.
# colorama is a Windows-only dependency, pinned for the laptop's sake.
#
# To move a pin: change it here, re-run the compile above, and let the next
# weekly run re-sync the box venv (infra/hetzner/cax11/run_pipeline.sh does it
# when this file or requirements.txt changes).
