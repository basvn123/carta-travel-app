# Config reference

Generated by `scripts/docs/config_reference.py` (ROADMAP B4, T1165). Never edit by hand: change the config, then run `python -I scripts/docs/config_reference.py`. CI runs it with `--check` and fails when a key was added or removed without regenerating this file.

305 keys in 6 files: 284 with a reader, 17 dead (no reader found), 4 notes for people.

How to read it:

- **Key**: a pricing rule (`stay.fees`), a top-level key, or one level into a block (`tiers.cutoffs`). Rows of a list are listed by id (`slots[flight]`). Keys starting with `_` or ending in `_about` are notes and not listed.
- **Value**: the value today, cut at 90 characters. Pricing values come from the rule's `value`.
- **Unit**: the rule's own `unit` in pricing.json; elsewhere read from the key's name, marked "(from the name)", or blank when the name says nothing.
- **Read by**: the first code lines that read the key (file and line on the day it was generated), found by reading the code: the quoted rule key, `section.key` on one line, an alias of the section, or the whole section iterated ("whole block"). Tests, `archive/` and the docs scripts do not count. Line numbers move with every edit; regenerate to refresh them.
- **For a traveller**: what changing the key changes for someone using Carta. "None directly" marks a pipeline or bookkeeping key.
- **Handbook**: the section in `docs/HANDBOOK.md` that explains the rule, found by the key in backticks, else by the key's section.

The pipeline has no config file of its own: `pipeline/pricing_config.py` and `pipeline/rating_config.py` read pricing.json and rating.json, and `run_pipeline.py`'s quality hook reads `scripts/quality/rules.yaml` through `scripts/quality/engine.py`.
