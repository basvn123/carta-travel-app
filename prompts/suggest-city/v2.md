# suggest-city, version 2

The town scout's user prompt (supabase/functions/suggest-city, built by `suggest-city/prompt.mjs`) and its Gemini response schema. With Google Search grounding on, Gemini refuses a schema, so `groundedFormat` spells the same shape out in the prompt. The system slot holds `security-rules`. The offline `suggest-city` eval in `continent-app/scripts/eval/run.mjs` guards it (T1206).

## Changelog

- v2 (T1206, 2026-11-07): the traveller's wish and the candidate deck the client sends are fenced as data blocks (WISH and CANDIDATES, aiGuard.dataBlock with the call's nonce), as plan-day and parse-booking already were (register row T1137-c). The wish line points at the block instead of quoting the wish inline. Every other fragment is unchanged.
- v1 (T1140, 2026-11-06): the text as it stood in code at commit 55a09c9c01, moved byte for byte. The loader gives the same prompt as the code did (prompts/_golden).

## Fragments

Each fragment is the text between the two `~~~` lines under its name. `{{name}}` is filled in by the caller.

### intro
~~~
You are Carta's destination scout: given what a traveller wants, suggest up to 5 great towns or cities for a day trip from {{stayLabel}}.
~~~

### candidatesHeader
~~~
CANDIDATES (JSON, real destinations Carta already has day-planning data for; id, name, country, distance in km from the stay, traveller rating 0-10 when known, descriptive tags):
~~~

### rulesHeader
~~~
RULES:
~~~

### preferCatalogue
~~~
- Prefer a candidate from the list above (id present, inCatalog=true) whenever one genuinely fits: Carta already has rich day-planning data for it.
~~~

### beyondList
~~~
- If the traveller is clearly asking for something none of the candidates cover, you may suggest a REAL place beyond the list with inCatalog=false, its own name, country and approximate coordinates. Never invent a candidate id for a place that is not actually one of the candidates.
~~~

### count
~~~
- Return 3 to 5 suggestions, best fit first. Do not pad with weak fits just to reach 5.
~~~

### focus.nature
~~~
- They lean toward nature: parks, water, viewpoints, green space over indoor city sights.
~~~

### focus.city
~~~
- They lean toward the built city: streets, squares, architecture, museums.
~~~

### interests
~~~
- What they care about most: {{interests}}.
~~~

### wish
~~~
- Their own wish (the WISH data block below), treat as the main brief:
{{wishBlock}}
~~~

### noWish
~~~
- No specific wish given beyond the mood above: pick well-rounded, strong fits.
~~~

### language
~~~
- Write "why" and "country" in {{lang}}. Keep "why" to one short, concrete sentence.
~~~

### noDashes
~~~
- Never use em dashes or en dashes in any text.
~~~

### groundedFormat
~~~

OUTPUT FORMAT: reply with ONLY a single JSON object, no markdown code fences, no commentary before or after it, exactly this shape:
{"suggestions":[{"id":"candidate id string, ONLY when inCatalog is true","name":"string","country":"string","why":"one short sentence","inCatalog":true,"lat":0,"lon":0}]}
("lat"/"lon" only when inCatalog is false; omit "id" when inCatalog is false.)
~~~

### schema
~~~
{
  "type": "OBJECT",
  "properties": {
    "suggestions": {
      "type": "ARRAY",
      "items": {
        "type": "OBJECT",
        "properties": {
          "id": {
            "type": "STRING",
            "description": "Candidate id, required when inCatalog is true."
          },
          "name": {
            "type": "STRING"
          },
          "country": {
            "type": "STRING"
          },
          "why": {
            "type": "STRING",
            "description": "One short, concrete sentence: why this place fits the ask."
          },
          "inCatalog": {
            "type": "BOOLEAN"
          },
          "lat": {
            "type": "NUMBER",
            "description": "Only for inCatalog=false discoveries."
          },
          "lon": {
            "type": "NUMBER",
            "description": "Only for inCatalog=false discoveries."
          }
        },
        "required": [
          "name",
          "why",
          "inCatalog"
        ]
      }
    }
  },
  "required": [
    "suggestions"
  ]
}
~~~
