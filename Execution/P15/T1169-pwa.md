# T1169: Installable app, offline shell and kept trip (ROADMAP I7, PWA part)

Round 2 session S85, batch 10. Branch `p15-s85-pwa`.

## Date

2026-11-07

## What changed

Carta already had a manifest, a hand-written service worker and an install hint in My trips (T246, T272, T362), but the offline promise failed. The worker cached only four shell files at install. The entry script, its modulepreloads, the stylesheets and the boot index load before a new worker controls the page, so none of them were cached. Offline after a first visit showed a blank page. The worker's catch-all also cached same-origin `/api/*` answers (flights, forecast, Ask Carta), which are per request and per person. Now the worker (cache `carta-v8`) precaches every file `index.html` names. The page hands the worker the files it loaded before the worker took over, and the worker then fetches every lazy screen chunk the entry script names, once, in the background. `/api/`, `/functions/`, `/auth/` and any request that carries a credential header are never stored, and Supabase was already never stored. Offline, My trips shows one status line (`pwa.offline.*`, all six languages) and the trip kept on this device opens. On the fast build with the fixture catalogue, the new `scripts/verify_pwa.mjs` went from 7 of 15 checks to 15 of 15. Installability is checked with Chromium's own `Page.getInstallabilityErrors` (empty before and after). The install prompt stays at its one designed moment: in My trips, on a phone browser, after a trip is kept, never on the first run. Stores are later (T1169-c).

## Research

A research subagent compared the options on 2026-11-07. All four are MIT; versions are from npm.

| Option | Fit | Verdict |
|---|---|---|
| Keep the hand-written `public/sw.js`, precache from the build | No dependency, no CSP change, keeps the per-path rules (T054, T271, T646) | Chosen |
| vite-plugin-pwa 2.0.0 (Workbox 7.4.1) | `injectRegister: 'inline'` adds an inline script the CSP blocks (nonce issue #672 open); `generateSW` replaces the custom worker; `injectManifest` puts the worker through a build step | Not chosen |
| workbox-build 7.4.1 `injectManifest` | Works without an inline script, but needs a build step and Workbox releases are slow | Not chosen |
| Serwist (@serwist/vite 9.5.13) | Actively maintained, but injectManifest only, so the worker gets rewritten; adds zod and TypeScript peers | Not chosen |

The research pick for the precache list was a list written at build time from Vite's `.vite/manifest.json`. That means editing `scripts/build-pages.mjs`, which is outside this task's files. So the worker reads the list from the built page and the entry script it already caches. That needs no build step, and `tests/pwa.test.mjs` pins the parsing. The build-time list is row T1169-d.

Installability criteria: Lighthouse 12 removed the PWA category and pointed to Chrome's own criteria (manifest name, start_url, display, 192 and 512 icons, HTTPS, no `prefer_related_applications`). The check therefore asks Chromium directly through DevTools Protocol `Page.getInstallabilityErrors`, the same check as DevTools > Application > Manifest. Sources: [Chrome install criteria update](https://developer.chrome.com/blog/update-install-criteria), [web.dev install criteria](https://web.dev/install-criteria/), [Lighthouse v12.0.0](https://github.com/googlechrome/lighthouse/releases/tag/v12.0.0), [vite-plugin-pwa register docs](https://vite-pwa-org.netlify.app/guide/register-service-worker), [npm vite-plugin-pwa](https://www.npmjs.com/package/vite-plugin-pwa), [npm workbox-build](https://www.npmjs.com/package/workbox-build), [npm @serwist/vite](https://www.npmjs.com/package/@serwist/vite).

## What broke and how it was fixed

| What | Cause | Fix |
|---|---|---|
| Offline after a first visit was a blank page | The entry files load before the worker controls the page, and install cached only 4 shell files | Install precaches every file index.html names; the page posts what it already loaded (`carta:warm`) |
| `/api/*` answers were cached | The catch-all stale-while-revalidate rule covered every same-origin GET | A `NEVER` rule and a credential-header rule run before every other rule; bumping to v8 drops what v7 kept |
| My trips crashed into the error boundary offline | Its lazy chunk had never been fetched online | The worker fetches every chunk the entry script names, once, in the background |
| `Page.getInstallabilityErrors` said `in-incognito` | Playwright's `newContext` is incognito | The check uses a persistent profile in a temp folder |
| The app could not boot locally | The container has no `boot.json` or shards | The check serves the CI contract fixture, split the way `sync-data.mjs` splits the real catalogue |
| pytest: test_beauty_v2_reads_no_register and test_adding_places_moves_nobody_else fail here | `cache/unesco_whc.json` is a 131 byte Git LFS pointer in this container, not JSON; no Python was touched by this task | None needed in this task; CI checks out the real file |
| The account-host check flagged `/assets/supabaseClient-*.js` | A path regex matched the bundle name | The check compares cached hosts, not paths |

3. It is a status line (`role="status"`), not a banner over content, and it cannot be dismissed while it is true.

6. It shows on every width.

## Rollback procedure

Run `git revert` on the T1169 commits. Clients that installed worker v8 move to whatever worker is deployed next. That worker must carry a new `CACHE_VERSION` (for example `carta-v9`) so the v8 cache is cleared on activate. Nothing is one-way: no migration and no live data.
