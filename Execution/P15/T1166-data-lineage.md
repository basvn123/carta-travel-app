# T1166: data lineage and request path diagrams (ROADMAP B5, session S82)

## Date

2026-11-06

## What changed

Every one of the 76 wire fields in `docs/wire.schema.json` (33 meta, 43 destination) now has a lineage row: its source, the `run_pipeline.py` task that writes it, the intermediate artifact, the writer script, the wire file it lands in (boot index, rank tier, country shard, POI shard) and the app files that read it. The hand-curated half (source, task, artifact, writer) is `docs/architecture/lineage-fields.json`; the rest is generated by `scripts/docs/build_lineage.py` into `docs/architecture/lineage.md` from the contract, the `TASKS` list (read with ast), `bootIndex.js` (`BOOT_COLS`, `RANK_FIELDS`), `dataHost.js` (`R2_TIER`) and a pattern search of `continent-app/src` for readers. The same doc has one Mermaid diagram per pipeline task that writes a wire field or a wire file (42 of 78 tasks), a trunk diagram, and a table of the 27 wire files and folders beside the contract with task, writer, host and reader. `docs/architecture/request-paths.md` (hand-written from the code) has a Mermaid sequence diagram for each of the seven request paths: first load, Explore, place page, Plan, Ask, plan-day and account sync, with what is fetched from Pages, R2, Pages Functions, Supabase and third parties. `build_lineage.py --check` fails when a wire field has no row, a row names an unknown field or task, a writer is missing or does not name the field, a `writes_wire` task or an `R2_TIER` entry has no wire file row, a request path loses its section or diagram, or the request path doc names a file that is gone; `--strict` also fails on a stale `lineage.md`. Before: one overview diagram and five one-line request paths, no field lineage. No code changed.

The lineage surfaced gaps, now register rows: 26 shipped fields with no app reader found, 20 fields written by scripts no task runs, 2 fields with no writer left in the repo, and wire files no screen fetches (`joins.json`, `destinfo/`).
