# T1174: Data blog, part 2 (K14, S90)

## Date

2026-11-07

## What changed

The data blog (ROADMAP K14) now has four post types and a monthly routine. New: *What changed* (the ten largest moves in the price of a three star room between two snapshots), *New on Carta* (places in the wire that were not in the last snapshot) and *Lowest fare week* (per place, the week with the lowest return fare from one airport against its median week). Each writes the same draft and data file as part 1 and goes through `scripts/blog/check_draft.py`, which now also refuses a post whose earlier snapshot or fares file differs from the hash it cites, whose rows do not follow from that file, or that calls an old place new. Every run writes a small price snapshot to `content/blog/data/snapshots/` (committed with the drafts), so a month later the comparison data is in the repository. A new pipeline task `blog_pr` (monthly tier, follows `blog_drafts`) runs `scripts/blog/monthly_pr.py`, which checks the drafts, commits `content/blog/` to a branch `blog-drafts-YYYY-MM`, pushes it and puts the checkout back; it is a dry run until the owner sets `CARTA_BLOG_PR=1`. The December 2026 "Where to go" draft was regenerated from the current wire (2026-06-07) and is unchanged from part 1: it passes the check and stays `status: draft`. The comparison types and the fare type cannot have a real draft yet: there is one snapshot, and no fares export exists (T1174-a, T1174-c). They are tested end to end on fixtures. Nothing is published, nothing deployed, no model call was added.

## Research

None chosen. No tool, library, model, service or data source was picked: the new types reuse the part 1 stack (standard library, the wire, the check script). The one design choice, where "what changed" gets its earlier data, was between the git history of `app_data.json` (16 MB, not tracked per month), the pipeline's archive state (box only) and a small snapshot committed with the drafts; the snapshot won because the check can verify it by hash in CI and a month later it is in the pull request that needs it.
