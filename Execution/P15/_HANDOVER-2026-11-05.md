## 6. How the work was run (keep doing this)

- **Batches.** One batch branch, with each task as its own commit series. Parallel tasks run as subagents, each in its own worktree in `C:/Users/Gebruiker/Documents/Portfolio/wt/`, with `node_modules` linked as a junction.
- **Worktree cleanup.** Unlink the junction with `cmd /c rmdir`, then `git worktree remove`.
- **Register and docs.** Subagents never edit `_OPEN.md`, `ROADMAP.md`, `CLAUDE.md` or `MAP.md`; the batch lead adds their rows at merge. One batch report, one end check, one PR.
- **Model per task.** Opus for security, SQL and UX design; Sonnet for the rest.
- **Pushing a large batch.** GitHub refused one large push with "fatal error in commit_refs_rules". Pushing merge by merge (`git push origin <sha>:refs/heads/<branch>`) worked.
- **Reproducing CI.** Use a sparse worktree with LFS skipped (`GIT_LFS_SKIP_SMUDGE=1`). A local pass in the full checkout hides missing untracked files.
