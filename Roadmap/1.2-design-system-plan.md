# Roadmap 1.2: one design system for Carta

Plan written 2026-10-13 (T417). Roadmap item 1.2, week W43.

**Done when** (from the roadmap): every tab uses the same buttons, cards and price notation, and there is one place that shows each colour, type size, button, card, chip, filter, icon and price format with an example and a line on when to use it.

**Owner decisions taken 2026-10-13**

1. A new look, not a refinement. The cream ground, Fraunces display serif and terracotta accent are replaced through impeccable's direction round. The goal is professional, modern, simple, clean and dynamic, with no decoration that carries nothing.
2. Price notation: whole euros on cards, pins, lists, rails and filters; cents on receipts, totals, ledgers and pass prices. Symbol placement follows the locale everywhere (€87 in English, 87 € in German and French). This also closes the price half of roadmap item 1.8.
3. The roadmap lives in `Roadmap/` on main.

## 2. What survives the new look (product truth, not style)

These come from PRODUCT.md and are not reopened by the direction round:

- Numbers are an instrument. Measured facts (prices, dates, times, distances, counts) sit in a monospaced or tabular face with `tabular-nums`; prose never does. The face itself may change.
- Estimates carry a tilde and "est." in text, never colour alone.
- 44 px touch floor (`--tap`) on every control on touch; 360 px phone width without horizontal scroll.
- WCAG AA 4.5:1 for every text pair; visible focus on everything; reduced motion honoured.
- Six languages; no string built by concatenation; no em or en dashes, no middots, no banned words; sentence case.
- One primary action per view. Ratings never use the action colour. Destructive actions have their own colour.
- Motion tokens from T380 (`--dur-1` to `--dur-4`, two easings): kept, retuned if the direction asks.
- Light only, unless the direction round makes a case for dark and the owner approves it as its own decision.

Open for the direction round (old style rules, not product truth): the palette, all three faces, radius language, the selected state, shadows, the "no gradient anywhere" rule, photo treatment and caption bands, the ink-ramp place hierarchy.

## 3. The architecture of the system

### 3.1 Tokens in three layers

All in `continent-app/src/styles/01-tokens.css`, still the one source of truth.

1. **Primitives.** The raw palette as scales (for example `--neutral-0` to `--neutral-950`, `--brand-50` to `--brand-900`), the font stacks, the raw sizes. Components never read these.
2. **Roles.** What a value is for: `--surface`, `--surface-raised`, `--surface-sunken`, `--text`, `--text-2`, `--text-3`, `--border`, `--border-soft`, `--action`, `--action-hover`, `--action-text`, `--selected-bg`, `--selected-text`, `--focus`, `--measure` (ratings), `--gem`, `--positive`, `--caution`, `--danger`, plus the domain roles (water, trail, AI) the data drawings need. Components read only these.
3. **Component tokens**, only where a value is shared by one component: `--btn-h`, `--btn-h-sm`, `--card-radius`, `--chip-h`, `--icon-sm/md/lg`.

**Compatibility layer.** Every old token name (`--paper`, `--ink`, `--ink-fill`, `--accent`, `--rule` and the rest) becomes an alias of a new role in the same file. The day the new tokens land, the whole app re-skins at once with no component touched; migration then removes the old names file by file, and a lint rule stops new uses of them. This is the step that makes the new look visible on every tab in one commit, and revertible in one commit.

### 3.4 Money: one function, one component

`continent-app/src/lib/money.js`, and `<Money>` in `components/ui/`.

```
formatMoney(value, {
  precision: 'whole' | 'cents',   // card contexts whole, receipt contexts cents
  per: 'day' | 'night' | 'person' | 'trip' | null,
  est: false | true,              // adds the one estimate notation
  range: [low, high] | null,      // "€40 to €60"
})
```

Rules it enforces:

- Always `Intl.NumberFormat` with `style: 'currency'` and `activeLocale()`, so placement follows the language (€87, 87 €). No `€` in any i18n string again: strings take a `{price}` placeholder.
- Whole on cards, pins, lists, rails, filters and chips; cents on receipts, totals, ledgers, pass prices and the PDF. The context decides, never the call site's taste.
- One estimate notation: `~€87` with a separate "est." label (decided in T418 against the five existing ones; the landing promise "a tilde and est." stays true).
- One per-unit wording per unit, through i18n: "a day", "a night", "a person", "for the trip". No `/pp`, `/p`, `/day` in JSX.
- Ranges always "€40 to €60" through `formatRange`.
- A missing value never renders a blank or a lone dash: it shows the i18n word for "price on request".
- `<Money>` renders the figure in the number face with `tabular-nums` and updates in place through `settleFigure()`.

The PDF exporter (`destinationPdf.js`) and the admin tables use the same function; "EUR 12" disappears.

### 3.5 The style guide page

A route in the app, `?styleguide`, built from the real components (not a picture of them), hidden from navigation and excluded from the sitemap. Sections: colour roles with contrast ratios, type scale, spacing, radius, elevation, icons, buttons, chips and filters, cards, inputs, toggles, money (every precision and context, in all six languages), states. Every section says when to use it and when not to. This page is the "one place" in the roadmap's done condition, and it is the screen the owner approves on a phone.

### 3.6 Enforcement

`continent-app/scripts/ci/design-lint.mjs` gets new rules, each with a baseline so old code does not fail the build while it waits for migration:

- `raw-button-class`: a `<button>` with a new class that is not from `components/ui`
- `radius-literal`, `font-size-literal`, `space-literal`: a px value where a token exists
- `money-literal`: `€` or `EUR` in JSX or i18n, `toFixed` on a price, or a call to a retired money helper
- `legacy-token`: a new use of an old alias name

The baseline count per rule is the migration progress meter.

## 5. Risks and how the plan handles them

1. **Impeccable cannot see the context files.** `impeccable context` resolves to `continent-app/` (its own git repo) and finds no PRODUCT.md or DESIGN.md there; they live at the repo root. T419 fixes this before the direction round, by running impeccable from the root with an explicit target or by a pointer file in `continent-app`, decided in that task, so every later impeccable command loads the product truth.
2. **44,000 lines of CSS in 50 files, with the v6 sheets (60 to 69) overriding the older ones.** The compatibility layer means the re-skin does not depend on that tangle; the migration retires it surface by surface, and each task deletes the dead rules it replaces.
3. **Colours that live in JavaScript.** MapLibre paint colours sit in `src/map/tokenColors.js`, and the PDF has its own. Both are updated in T420 alongside the CSS; the `token-mirror-drift` lint rule catches a miss.
4. **Fonts.** A new face set means new self-hosted woff2 files (latin and latin-ext), new `@font-face` blocks in `index.html` and a check on the LCP budget from T011.
5. **Two git repos.** All app work commits inside `continent-app/` as well as the root; every task checks `git -C continent-app status` before its report.
6. **Six languages.** Button and chip labels are tested at the longest translation (usually German) in the style guide, and money in all six.
7. **Production.** Nothing in this plan deploys. Each step lands on its branch; going live stays an owner step through the runbook.
